## 1. Отримання Assembly (arithmetic.c)

**Відповідь на питання:** Для обчислення `a + b` процесор повинен завантажити значення `a` у регістр, завантажити значення `b` в інший регістр (або використати пам'ять), виконати інструкцію додавання (add) і зберегти результат.

**Відповіді на питання:**

1. _Чи кожному рядку C відповідає рівно одна Assembly-інструкція?_ — Ні. Один рядок C може перетворитися на кілька інструкцій (наприклад, завантаження в пам'ять, додавання, збереження).
2. _Чи бачите ви в Assembly змінні з назвами a, b, result?_ — Ні. Assembly працює з регістрами та адресами пам'яті (наприклад, `[rbp-4]`), а не з іменами змінних.
3. _Скільки Assembly-інструкцій приблизно відповідає тілу main()?_ — Близько 10-15 інструкцій (включаючи підготовку стеку та виклик printf).
4. _Чи присутня операція додавання?_ — Так, інструкція `add`.

## 2. Арифметичні операції (operations.c)

| C       | Основна Assembly-інструкція |
| :------ | :-------------------------- |
| `a + b` | `add`                       |
| `a - b` | `sub`                       |
| `a * b` | `imul`                      |

**Пояснення:** При зміні операції в C змінюється лише одна інструкція в Assembly (наприклад, `add` на `sub` або `imul`). Решта коду (підготовка стеку, виклик функції) залишається незмінною.

## 3. Реалізація if (condition.c)

| C            | Assembly                                                                              |
| :----------- | :------------------------------------------------------------------------------------ |
| `if (a > b)` | `cmp a, b` (порівняння) та умовний перехід (наприклад, `jle` — jump if less or equal) |
| `return a`   | `mov eax, a` (запис у регістр результату)                                             |
| `else`       | `jmp` (безумовний перехід, щоб пропустити блок else)                                  |
| `return b`   | `mov eax, b`                                                                          |

**Відповідь:** Машинної інструкції `IF` не існує. Процесор реалізує умову через комбінацію порівняння (`cmp`) та умовного переходу (`jle`, `jg` тощо). Якщо умова виконується, процесор переходить за однією адресою, якщо ні — за іншою.

## 4. Реалізація циклу (loop.c)

- **Порівняння:** `cmp` (порівнює лічильник `i` з `n`).
- **Перехід:** умовний перехід (наприклад, `jle` — jump if less or equal), який повертає виконання на початок циклу.
- **Чи є поняття for?** — Ні, в Assembly немає циклів `for`. Є лише інструкції порівняння та переходи.
- **Як CPU визначає, що цикл потрібно повторити?** — За допомогою прапорців (flags), які встановлюються після інструкції `cmp`. Якщо умова (наприклад, `i <= n`) істинна, виконується перехід на початок тіла циклу.

## 5. Виклик функції (operations.c)

- **Виклик:** Інструкція `call calculate`.
- **Початок функції:** Мітка `calculate:`.
- **Завершення:** Інструкція `ret`.
- **Регістр результату:** `eax`.

**Відповідь:** Після `call` процесор зберігає адресу наступної інструкції (return address) у стеку. Коли функція завершується, інструкція `ret` бере цю адресу зі стеку і повертає виконання туди, звідки була викликана функція.

## 6. Machine Code (objdump)

Я виконав `objdump -d -M intel arithmetic.exe` і знайшов функцію `<main>`. Ось три інструкції з її машинним кодом:

| Address       | Machine-code bytes     | Assembly                      | Пояснення (C-код) |
| :------------ | :--------------------- | :---------------------------- | :---------------- |
| `0x1400014dd` | `c7 45 fc 05 00 00 00` | `mov DWORD PTR [rbp-0x4],0x5` | `int a = 5;`      |
| `0x1400014f1` | `01 d0`                | `add eax,edx`                 | `result = a + b;` |
| `0x140001502` | `e8 29 09 00 00`       | `call 140001e30 <printf>`     | `printf(...)`     |

**Відповіді:**

1. _Що зберігається у виконуваному файлі?_ — Machine code (байти).
2. _Навіщо objdump показує Assembly?_ — Це зручне представлення для людини. objdump перекладає байти назад у текст, щоб програміст міг їх аналізувати.
3. _Чи всі інструкції однакові за розміром?_ — Ні. В x86-64 інструкції мають змінну довжину (від 1 до 15 байт). Наприклад, `add` — 2 байти (`01 d0`), а `call` — 5 байтів (`e8 29 09 00 00`).
4. _Чому Assembly зручніше?_ — Тому що читати `add eax, edx` набагато простіше, ніж `01 d0`.

## 7. Оптимізація (-O0 vs -O2)

При компіляції з `-O2` компілятор:

- Прибирає зайві завантаження та збереження в пам'ять.
- Використовує регістри замість пам'яті.
- Може вбудувати (inline) функцію `calculate` безпосередньо в `main` (без інструкції `call`).
- Може обчислити результат під час компіляції (constant folding), якщо всі аргументи відомі.

**Чому компілятор може замінити `10 + 20` на `30`?**
Тому що результат виразу є константою, і його обчислення під час виконання не має побічних ефектів. Компілятор оптимізує код, щоб він працював швидше, не змінюючи поведінку програми.

## 9. Відповіді на контрольні питання

1. **Що таке ISA?** — Це архітектура набору інструкцій (Instruction Set Architecture). Це "мова", яку розуміє процесор (наприклад, x86-64, ARM).
2. **Чому CPU не може безпосередньо виконувати C-код?** — Тому що C — це мова високого рівня, призначена для людей. Процесор розуміє лише двійкові машинні інструкції.
3. **У чому різниця між Assembly та machine code?** — Assembly — це текстова, зручна для людини вистава машинних інструкцій. Machine code — це реальні байти (0 та 1), які процесор виконує безпосередньо.
4. **Що робить параметр GCC `-S`?** — Він зупиняє компіляцію на етапі генерації Assembly-коду, не створюючи об'єктний файл.
5. **Навіщо ми використовували `-O0`?** — Щоб вимкнути оптимізацію. Це дозволяє побачити "сирий" код, де кожна дія C відповідає інструкціям Assembly, без спрощень.
6. **Що таке operand?** — Це операнд, аргумент інструкції (наприклад, регістр або адреса пам'яті), з яким виконується дія.
7. **Для чого використовується `mov`?** — Для переміщення даних між регістрами або між регістром і пам'яттю.
8. **Яку роль виконує `cmp`?** — Вона порівнює два значення (віднімає одне від одного) і встановлює прапорці (flags), але не зберігає результат.
9. **Як на машинному рівні реалізується `if`?** — Через комбінацію `cmp` (порівняння) та умовного переходу (`jle`, `jg`, `je` тощо).
10. **Як реалізується цикл?** — Через `cmp` та умовний перехід, який повертає виконання на початок циклу, поки умова істинна.
11. **Для чого потрібна інструкція `call`?** — Вона викликає функцію, зберігаючи адресу повернення в стеку.
12. **Для чого потрібна `ret`?** — Вона повертає виконання з функції, беручи адресу повернення зі стеку.
13. **Чому одному рядку C не обов'язково відповідає одна машинна інструкція?** — Тому що компілятор може розбити один складний вираз на кілька простих кроків (завантаження, обчислення, збереження).
14. **Що показує `objdump -d`?** — Він дизасемблює виконуваний файл, показуючи машинний код (байти) та його Assembly-представлення.
15. **Чому Assembly, отриманий з `-O0` та `-O2`, може суттєво відрізнятися?** — Тому що `-O2` оптимізує код: прибирає зайві операції, використовує регістри замість пам'яті, вбудовує функції (inlining) та обчислює константи.
16. **Чи може компілятор повністю видалити частину написаного програмістом C-коду?** — Так, якщо цей код не впливає на результат програми (наприклад, обчислення, результат якого ніде не використовується, або константи, які можна обчислити під час компіляції).
